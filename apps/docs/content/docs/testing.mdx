# Testing

The repository uses fast tests for core and React behavior, then Playwright for browser-only behavior.

```txt
Vitest + React Testing Library + jsdom
```

This covers parsers, source resolution, player lifecycle, state transitions, controls, custom controls, keyboard behavior, accessibility queries, and component state without requiring real media decoding.

## Commands

```bash
npm run typecheck
npm run test
npm run build
npm run test:e2e
```

Use `npm run test:all` when you want the full local verification chain.

## Unit tests

Core tests should avoid real media decoding:

```txt
source resolver
VTT parser
thumbnail parser
state transitions
plugin lifecycle
safe play rejection
volume/seek clamping
```

Use fake or custom engines for state transitions that need engine events. Do not depend on a browser actually decoding a video in unit tests.

## React tests

React Testing Library should test user behavior:

```tsx
await user.keyboard('{Space}')
expect(screen.getByRole('button', { name: /pause/i })).toBeInTheDocument()
```

Recommended React test coverage:

- default player renders
- custom controls can replace default controls
- keyboard shortcuts work
- shortcuts ignore inputs
- fullscreen updates focus/state
- mini-player uses compact controls
- bottom progress only renders in mini mode
- thumbnail preview sizing/gap is applied

Prefer user-visible assertions and role/name queries. That catches broken labels and focus regressions better than class-only assertions.

## Playwright tests

Use Playwright for browser behavior that jsdom cannot prove:

```txt
Chromium desktop
Firefox desktop
WebKit desktop
Mobile Chrome profile
Mobile Safari profile
```

Run locally or in CI after installing browsers:

```bash
npx playwright install chromium firefox webkit
npm run test:e2e
```

Keep Playwright smoke tests focused. Most behavior should stay in fast Vitest/RTL tests.

Use Playwright for fullscreen, PiP availability, real browser media policies, mobile viewport behavior, and docs/playground smoke tests.
