# Accessibility

A video player is interactive UI, not just media. Treat every control as part of your app's accessibility surface.

## Baseline rules

- Every button needs an accessible label.
- The player root should be focusable when keyboard shortcuts are enabled.
- Menus must trap and restore focus correctly.
- Fullscreen should return focus to the player root after state changes.
- Disabled controls must be visibly and semantically disabled.
- Do not hide controls from keyboard users just because pointer controls auto-hide.

## Captions

Provide captions where possible:

```tsx
<VideoPlayer
  src="/video.mp4"
  subtitles={[
    {
      src: '/captions.en.vtt',
      label: 'English',
      lang: 'en',
      default: true,
    },
  ]}
/>
```

## Current Root Behavior

The default player root is focusable, labelled as `Video player`, and receives keyboard shortcuts when focused. Fullscreen toggles return focus to the player root after the browser API settles.

Shortcuts are ignored for inputs, textareas, and contenteditable elements so forms and custom text fields remain usable.

## Custom Controls

When replacing controls with slots or children, preserve accessible names and button semantics.

```tsx
function MyPlayButton() {
  const isPlaying = usePlayerState('isPlaying')
  const remote = usePlayerRemote()

  return (
    <button type="button" aria-label={isPlaying ? 'Pause video' : 'Play video'} onClick={remote.togglePlay}>
      {isPlaying ? 'Pause' : 'Play'}
    </button>
  )
}
```

## Testing accessibility behavior

Use React Testing Library queries by role and accessible name:

```tsx
expect(screen.getByRole('button', { name: /play/i })).toBeVisible()
```

This catches broken labels earlier than visual-only tests.
